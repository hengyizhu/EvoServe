3. 预检与校准
每张卡：
- 20 次推理暖机、至少 100 次稳定 serving-only 请求；记录模型执行与客户端延迟。
- 5 次完整 optimizer 暖机，30 次稳定更新；optimizer 状态已创建后记录峰值。
- 训练和推理分开使用固定输入、噪声/时间样本和 RNG；不能在推理线程反复设置全局 seed 干扰训练。
- 给推理标记 I_PREFIX（视觉+语言前缀）、`I_ACTION`（全部现有去噪/flow steps）、`I_POST`。
- 给训练标记 T_FWD、`T_BWD`、`T_OPT`（含梯度处理、step、zero_grad）。
- 校验从 forward 到 backward 之间暂停不会改变计算：同一输入流跑 5 个完整更新，与未分段路径比较 loss、梯度与最终可训练参数。记录冻结参数与生产参数校验。
- 不在图中添加设备全局同步。片段完成由 CUDA event 或所属 stream 完成事件判定；不能用 Python 函数返回当作 GPU 已让出。
若训练/推理放不下，记录失败并停止该负载。不得为了放下而静默更改精度、冻结范围或 offload。

5. 主回放工作负载
本部分是 GPU 机制微基准，deadline 是控制需求的参数化抽象，不是从旧同步 rollout 推导出的物理动作队列。
- 两个模拟需求源，各自按固定周期 P 发出真实模型输入；请求数量不因前一个请求变慢而减少。
- 依据 serving-only 校准的 mean service cost c，固定两个 nominal load：0.40 和 0.70。
- 共同周期 P = ceil_to_50ms(2*c/rho)。多个 GPU 比较使用事先选定的共同保守 c；每个 GPU 仍报告本卡基线。c 只能来自 serving-only 校准，不根据候选模式结果调整。
- 每请求 release = offset + k*P，`deadline = release + P`。
- 同步模式 offsets=[0,0]；错峰模式 offsets=[0,P/2]。二者平均需求相同。
- 所有模式接收相同输入、释放时刻、deadline。提供预测信息的模式使用同一份有限前瞻信息；此回放中的周期性信息是受控输入，不冒充真实动作队列预测器。
- 每个条件暖机 20 秒、测量窗口 180 秒、三轮；结束后停止新到达并单列排空，最多 60 秒，超时未完成计入违约。
- 训练吞吐只统计共同的 180 秒窗口内完成的 optimizer updates 和对应有效样本；partial accumulation 不冒充完整更新，排空期单独计。
- P99 保留数值和样本量，首轮主比较使用 deadline miss、P95 与训练进度；不能将少数尾样本解释为稳定 P99 保证。
四个 workload = 两种负载 × 两种相位。
6. 五种模式（主实验）
S0 serve_only: 只推理。

S1 queue_priority_coarse: 当前就绪请求优先；队列为空时最多提交一个完整训练 microbatch（FWD+BWD），在其 GPU 完成后重新调度。保持原梯度累积与 optimizer 边界。

S2 deadline_admission_coarse: 与 S1 相同训练片段，但在提交之前使用当前及下一轮期限需求进行 EDF 可行性检查；推理成本、训练成本和安全余量来自独立校准。

S3 queue_priority_split: 与 S1 相同信息，合法暂停点扩展到 FWD 完成、BWD 完成、OPT 完成；反向前保留计算图，不能丢弃/重算而不计成本。

S4 deadline_admission_split: S2 的同一准入规则 + S3 的同一执行切分。

规则：
- S2 与 S4 使用完全相同预测信息、成本估计与安全余量。
- S1 与 S3 使用相同当前队列；不得延迟生成器以降低负载。
- 推理在本轮按完整 request 执行，不改变其数学与 batching 方式。
- 内存相同条件下，S1/S2 不得故意一次排队多个尚未开始的训练片段。
- 每种模式从相同候选 checkpoint、optimizer 状态、数据游标开始；只在完整 optimizer 边界更新参数，保持有效 batch 与样本顺序。
- 不在 backward hook 中 sleep；不把 action-token 拆成新训练样本；不改损失、去噪次数或训练目标。
- 给所有方法充分但相同的预热；编译开关继承已验证配置，不为某一个模式单独编译优化。
- S2/S4 的准入：假设候选片段占用资源至 t+T_u，随后按 EDF 推进窗口内已知/预测的推理工作，所有预计完成时间加 margin 均不超过其 deadline 才准入。不是只检查队列此刻为空。
- margin 可取 max(10ms, calibration_p95-calibration_mean)，在全矩阵运行前冻结，不能按方法调参。
每张主要 GPU 的基础矩阵为 5×4×3=60 组。180 秒仅是测量窗口预算，不含实现、加载、暖机和排空。
7. 阶段重叠微基准（GPU 3）
比较两种实际推理阶段 × 两种真实训练片段：
	T_FWD	T_BWD
I_PREFIX	pair 1	pair 2
I_ACTION	pair 3	pair 4


- 在同一进程的两个 CUDA streams 中用独立模型实例执行；互相依赖部分使用 event。不要依赖无 MPS 多进程天然并行。
- 采用已有模型真实计算，不能用 sleep、无效 kernel 或人工 GEMM 代替。
- 为 T_BWD 准备所需前向和激活；为 I_ACTION 准备匹配的前缀 KV。准备成本在阶段隔离微基准中单列，不能因此声称端到端加速。
- 每对先测两项独占成本，再测联合 wall time；两种启动顺序轮换。至少每对 100 次有效试验，保留分布。
- 不在正在读取候选权重的其他片段期间更新该权重。pair 结束后完成其剩余训练语义再进入下一试验。
- 测 infer_slowdown = inference_pair_time / inference_alone_time；`pair_gain = (infer_alone + train_fragment_alone) / joint_wall_time`。两项均报告。
- 同时测连续 prefix+action 的完整推理路径，校验提取后的路径输出与原 sample_actions 一致。
- 若没有真实 overlap，Nsight Systems 显示出来并如实报告；不要用 CPU enqueue 重叠当成 GPU 并发。
- 仅抽取少量代表区间做 Nsight Systems；Nsight Compute 的默认 kernel replay 会影响并发，今晚不做全程 NCU。
这项提供硬件机制证据，不等同于完整训练迭代吞吐或新的机器人任务成功率。
