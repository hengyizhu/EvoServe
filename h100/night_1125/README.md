# A6000 执行层证据复测

本队列从 `a3146654` 分支出来，在原布局实验主机上使用原 Python 环境、模型、固定样本库和 graph/manual 推理计划。单卡标定取布局记录中的 105.54721183143556 ms。每张卡使用独立的无配额 MPS daemon 和 8 个物理 CPU 核。训练固定 microbatch 4 × 累积 2，图外执行优化器。开关训练图时都保留 GPU 组 batch。

- 并发预检使用原 `h100/supplement.py` 的 export 模式，2 台机器人、总请求率 8 Hz，300 秒，对照原布局的 `cap-2.json`。各卡初始加载时间可能略有差异。
- `campaign.py` 核对预检、选择并行或串行、逐点启动和写报告。建表扫描中每点固定 m，保留反馈和 200 ms 余量保护。各点的顺序按轮随机排列；每个 seed 决定周期流的初相。三次实验均重新加载模型和训练执行器。
- `measure.py` 记录全部请求，以及正式 300 秒内完成的训练更新。A0、A1、A2 比较固定为 r32、单专家。A1 在初始化后清空缓存；测量中用同卡训练进程和冻结的 VLM 计算每个样本的首次前缀。A0/A1 不需要服务端导出，A2 每 104 个请求抽取 8 个。三组沿用同一组 16 个固定输入。分开计数训练前向、服务前向和 KV 导出。
- `decision_replay.py` 使用约十小时实时记录中的末 360 个五秒窗口，按真实节拍回放两个控制器。输入账本保留此前的请求。分两种范围测量决策耗时，分别是统计完成后的策略计算、以及包含账本扫描的决策。另行核对结果是否与原日志中的命令一致。
- `results/night_1125_A/` 放报告、逐点数据、预检和决策样本。工作目录 `/var/tmp/night1125/raw/` 保存每次实际运行的配置、日志和结果。控制器表中 0 代表没有通过的宽度，缺测保留空值。
